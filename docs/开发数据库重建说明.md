# 开发数据库重建说明

日期：2026-11-03

开发阶段、目标库数据确实允许丢弃时，空库重建能让实际结构与当前代码基线保持一致。但删除数据库会丢失所有商户、订单、库存卡密、凭证和幂等记录，不能把它称为比保留数据升级“更安全”的方案。

## 当前唯一入口

```text
shop-b2b2c-backend/src/main/resources/db/schema.sql
```

原`002_inventory_reservation.sql`和`003_order_idempotency.sql`已完整合并，并移除独立文件。当前schema包含全部14张表、预占到期复合索引、幂等主键及演示数据；先创建全部表，再插入种子。索引在建表语句中定义，不会在每次启动时重复执行独立CREATE INDEX。

schema不再创建或切换固定名称的数据库，只操作数据源URL或mysql导入命令选定的连接库。演示商品6现为类型3定制服务，与当前履约规则一致。已有数据不会因重复执行种子而被强制改写；这也意味着旧商品类型错误不会仅靠重启自动修正。

## 云端开发库重建步骤

1. 停止后端及所有连接该库的任务，避免删除过程中继续产生订单或预占；确认当前运行的是开发环境。
2. 核对数据库名与数据源URL、部署环境中的DB_NAME一致。需要保留的数据先导出并检查备份；不能保留的环境才适合继续重建。
3. 在数据库管理工具中，仅删除已确认的开发库，再创建同名空库，字符集为utf8mb4。不要删除MySQL系统库或其他项目库；保留应用账号并确认其对新库仍有建表、索引和读写权限。
4. 部署包含最新schema的后端产物。启用`SPRING_SQL_INIT_MODE=always`，并确保没有用环境变量把`SPRING_SQL_INIT_CONTINUE_ON_ERROR`覆盖为true。
5. 启动后端，让Spring Boot执行完整schema。SQL错误现在会阻止启动，必须查看日志解决，不能靠忽略错误继续运行。
6. 确认14张表存在，尤其是inventory_reservation、order_idempotency；确认预占索引idx_reservation_expiry包含status和expires_at，检查演示商品/账号后再进行功能测试。

如果连接URL有createDatabaseIfNotExist=true且应用账号具备相应CREATE权限，驱动也可以创建不存在的库。手动创建同名空库更容易明确库名、字符集和权限；不具备建库权限时，必须由数据库管理员先建空库，不能指望schema解决连接失败。

自动加载只有db/schema.sql，不会扫描历史迁移目录。关闭SQL初始化的环境可以向正确的空库显式导入这个完整文件，不能一边关闭初始化、一边期待启动自动补表。腾讯云基础设施脚本也导入同一份schema，重复导入与后续启动允许重复建表/种子检查。

## 重启与重建的区别

- 空库：创建全部结构及演示数据。
- 已有且结构一致的库：跳过已有表及重复种子，不清空业务数据。
- 已有但结构过时的库：不会自动ALTER旧列、修复旧索引或变更已有种子值。允许丢弃的开发数据可按上面步骤重建；必须保留数据时另行设计版本迁移和回滚方案。

schema本身不包含DROP、TRUNCATE或DELETE命令，启动不会主动删除数据库。但删除后重建会恢复演示数据和演示账号，不等于生产初始化或真实渠道进件；有真实数据的环境不应套用本说明。

## 验证方式

新增SchemaInitializationTest检查启动只加载一个schema、SQL失败不被吞掉、没有删库/跨库语句及重复独立建索引。新增SchemaMySqlTest在本机MySQL8程序启动的临时实例上执行**原始完整schema**，不是H2改写版：

- 使用--no-defaults、随机空闲端口及target下独立数据目录，不读取现有MySQL服务配置；核实@@datadir后才写入。
- 检查14张表、预占索引列顺序、定制服务种子及当前连接库，验证没有隐式创建shop_b2b2c固定库。
- 修改隔离库库存并新增幂等记录，再执行一次完整schema，检查不报错、行数不变、修改后的数据保留。
- 测试停止自己创建的实例，保留target下日志和临时数据用于排查；从未连接开发业务库、生产库或云端数据库。

在后端目录可显式运行本机MySQL验证（程序目录按实际安装位置填写）：

```powershell
mvn '-Dschema.mysql.bin=C:\Program Files\MySQL\MySQL Server 8.0\bin' clean test
```

默认`mvn test`仍运行普通单元/H2回归；没有提供schema.mysql.bin时，独立原生MySQL测试跳过，不会擅自连接本机3306端口或使用环境中的数据库账号。H2测试结构仅为隔离夹具，不是第二个运行时SQL入口。
