## 2. 交互规则

1. 列表列使用 `collectionModeView(商家配置, 总闸)` 计算：
   - 总闸未获取：显示“总闸状态未获取”，不默认成直收；
   - 应急关闭或总闸关闭：显示“商家直收”；商家配置为平台代收时附加“总闸未开”；
   - 总闸开启：按商家配置显示“平台代收/商家直收”。
2. 总闸开关：
   - 环境应急关闭时开关禁用并展示警示；
   - 更新成功提示“仅对新订单生效”；失败保留原值并刷新服务端状态。
3. 切换弹窗：
   - 展示商家配置模式、当前生效模式、平台总闸、环境应急、支付渠道、进件绑定状态；
   - 未就绪时禁用“平台代收”选项与“确认切换”，并展示 M1 返回的 `blockReason`；
   - 目标模式与当前配置相同时禁用确认，避免无效审计；
   - 成功后刷新详情、审计、总闸与商户列表。
4. 页面文案不得出现“审核中”兜底或写死银行名；进件状态由 M2 规则统一展示。

## 5. 未验证项与已知问题

1. **未执行验证**：`node --test` 与前端生产构建均由用户运行，本轮未运行。
2. **无浏览器视觉回归**：未截图确认弹窗在窄屏/长文案下的布局，需用户验收。
3. **无真实渠道数据**：多数商家 `bindingStatus` 为空，切换平台代收会被后端 409；页面禁用是预期行为，不是接口失败。

5. **权限**：页面位于超管后台，后端仍强制 `SUPERADMIN`；若后续开放运营角色，需另行设计权限与审计。
