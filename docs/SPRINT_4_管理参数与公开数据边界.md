## 管理参数规则

- 佣金允许0–100%，最多两位小数；月费允许0–99999999.99元，最多两位小数。校验在读取和写入店铺前完成，非法值不会改变原数据。
- 营业状态只能为0、1、2、3；收款模式只能为A、B、C。服务费状态兼容现有两套编码 NORMAL/TRIAL/OVERDUE 与 EXEMPTED/ARREARS，但拒绝其他值，D33的枚举统一尚未处理。
- 店铺资料更新限制公告512字符、Logo地址255字符、联系电话32字符、收款码地址512字符；必须绑定当前店铺。这里只校验长度，未宣称验证外部URL真实性或电话号码归属。
- 新建商户必填店铺编码/名称、经营者信息、联系方式、管理员账号和显式密码，并按数据库列限制长度。商户类型如传入须为1–3；结算账户文本也受长度校验。
- 密码至少8字符且UTF-8编码最多72字节，避免BCrypt截断；删除缺少密码时自动使用admin123的后端逻辑。既有演示账号、前端预填密码和密钥治理仍属D21后续范围，本轮没有批量改密。

本轮为基础参数边界，未实现身份真实性核验、渠道进件或完整密码策略；不得因此把F02或D13标为全部完成。

## 公开响应兼容

`/api/v1/public/products/{id}` 与 `/api/v1/public/orders/quick-search` 的 `data.store` 只包含：

```text
id, storeCode, storeName, logoUrl, notice, contactPhone
```

字段白名单使用独立不可变record，后续往MerchantStore加字段不会自动公开。店铺不存在时保留null。现有商城使用的名称、Logo、公告及客服字段保持兼容。授权后的平台商户管理和商家自己的资料接口不受此响应缩减影响。

本轮没有改造查单身份验证，也没有缩减quick-search中的订单/明细实体。D19、D20等凭证与查单边界问题继续独立跟踪，不因隐藏店主身份字段而被视为解决。
