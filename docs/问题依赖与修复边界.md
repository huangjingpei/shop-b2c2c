# 问题依赖与修复边界

日期：2026-11-04。P0–P3为优先级，D为缺陷编号，F为功能缺口编号。

## 处理原则

- 每轮锁定原编号、实际子范围和共同根因；共用规则放到一个实现入口，前端不再各算一套。
- 修复一个子问题不等于整个业务域完成；无人工反馈的交付保留待验证，Sprint 11/12验收由用户自行管理，不作为后续独立开发的前置任务。
- 依赖尚未实现时明确不可用，不用模拟状态、0金额或宣传文案掩盖缺口；原有接口键尽量保留，新语义明确记录。
- “避免二次修复”指避免重复建设和相互覆盖，不禁止修Bug。发现错误须记录根因、影响及回归用例；依赖功能落地后的接口扩展也应按原编号联动，不混作新需求。

## 当前聚焦：D25与D26商家看板

订单分类统一在`OrderStatistics`，平台和本店都消费该口径；前端工具只格式化字符串和未知值。以后D30改SQL聚合，须继续满足该DTO与用例，不能重新按页面定义GMV。

本轮只提供订单状态视角的历史支付、待付款意向、关闭/退款状态数量与预计佣金；实际退款、净额、已结算收入留空且标明账本不可用。F05增加部分退款等事件后应保留原订单金额快照，以事件计算实际退款/净额，不覆盖payAmount或把REFUNDED订单金额直接当退款总额。F03/F09接入后才增加渠道确认的结算指标。

本轮D26只处理商家看板营业状态、零费率和写死的渠道生效文案；商城Store.vue空店展示、公告及客服电话、公开店铺读取仍在原条目中单独保留。没有新增营销、会员或其他独立业务方向。

## D26商城店铺页后续范围（Sprint 14）

独立公开查询复用PublicStoreView六字段，contactPhone延续既有公开契约，不新增个人资料字段。仅status=1公开，其他状态与不存在统一不可用；这是沿用商品浏览资格的实现细化，不代表新增认证制度。空商品列表不再决定店铺存在性，店铺资料和商品错误分开。

D26商城与商家看板代码范围均已提交实现，人工验证未执行，因此台账仍保留进行中；D25资金账本及D30分页/N+1查询继续独立保留，不通过此次页面改动宣称解决。后续优化复用此接口和白名单，避免再从商品反推店铺。

## D30公开商品列表后续范围（Sprint 15）

公开列表复用既有营业/上架状态与SKU可售数量，改为组合条件及单SQL聚合；PublicProductView锁定原11个展示字段，保留data数组。D26独立店铺接口不依赖是否有商品，继续保留。库存聚合必须同时匹配SKU商品和商户，不能为优化查询取消归属校验。

尚未分页，管理端商品、订单与卡密查询也未改；后续优化不得改D25统计口径，或未经消费方适配将数组替换成分页对象。D30仅此子范围实现，待人工验证，真实MySQL及性能验证尚未执行。

## D33代付状态编码（Sprint 16）

PeerStatus集中定义现有INIT、RESERVED_LOCK、PAID、EXPIRED、CANCELLED字符串编码，实体默认INIT，建单/预占/释放/付款/到期及统计消费复用。数据库和前端继续使用原字符串契约，不引入新的转换层。SQL与隔离夹具默认值由契约用例约束。

这一步不改变D10/F08的超时规则、支付CAS前提或D25统计口径，不新增取消订单能力；保留CANCELLED编码不代表该业务已实现。未知旧值不自动转换成可预占/可付款状态。服务费NORMAL/TRIAL/OVERDUE与EXEMPTED/ARREARS的兼容和规范化仍归D33后续范围，待确认旧值含义后处理，不能借状态常量整理改变收费政策。

## D33服务费状态兼容（Sprint 17）

后续静态核对确认后端已接受五种服务费编码，本轮将该既有集合统一到ServiceFeeStatus及前端选项，分别展示/编辑，不将TRIAL与EXEMPTED或OVERDUE与ARREARS合并。Schema只补全说明，未修改结构或数据。未知值不伪装NORMAL；局部更新未传状态继续保留原值。

服务费标记、免费截止日和店铺营业状态分别维护。本轮不实现扣费、按日期自动转态或欠费停服，不以配置标签推断已生效。代付与服务费两个D33子范围均有实现及用例，仍待人工验证；以后若收费政策要求编码归并，应另外定义迁移及生效规则，不能直接替换历史值。

## D34打包/构建与D35运行部署（Sprint 18）

阿里云源码包生产者与03-build.sh消费者一起匹配当前三个工程，依赖锁文件及独立发布目录；完整三端产物全部校验后才能切换latest。产物名称仍保留历史阿里云布局，避免在构建修复中顺带改变部署消费者契约。

构建不执行测试或数据库操作，也不等于服务启动及健康通过。D35仍须核对04-deploy.sh、服务配置、Nginx、/m子路径和公开URL；D37依赖就绪探针独立处理。腾讯云脚本本轮未改。后续运行部署适配应消费已校验的发布目录，不能再次用目录可选跳过掩盖缺端，或拿假构建用例代替线上演练。

## D35通用网关与运行部署（Sprint 19）

通用nginx.prod.conf以商城根路径、管理端/console为统一参考；部署入口与路径约定文档解释与阿里云/m候选包、腾讯云旧脚本的关系。真实Nginx隔离用例负责URI、SPA、静态资源及应用存活转发，不替代真实三端/TLS联调。

/healthz只代理现有应用存活接口，不检查依赖；D37后续就绪接口须显式新增和适配，不能因本轮拒绝静态假成功而宣称交易就绪。云端部署脚本和证书尚未统一，后续应一并核对产物消费者、公开URL、回滚和失败阻断，不再次回到旧/m或Actuator入口。

## D37就绪检查与发布消费者（Sprint 20）

新增/api/v1/auth/ready及通用/readyz，腾讯云发布检查消费就绪接口；原health保持存活含义。DB SELECT 1、Redis PING/INFO只检查有限依赖条件，不写业务数据，不证明Schema、Redis键写权限或渠道可用。两线程无队列、等待预算与缓存限制故障放大，异常/未知状态不能改成UP。
