## 库存规则

`product_sku.stock_quantity` 表示可售库存。预占成功时立即减少；取消或超时将预占从 HELD 条件迁移为 RELEASED，再增加库存。支付将 HELD 改为 CONSUMED，不再重复扣库存。两步操作与订单状态更新在同一数据库事务中完成，任何失败一起回滚。

每个订单仅有一份预占记录，包含 SKU、商品、商户、数量、所有者凭证和截止时间。重复释放不会重复加库存；取消后重新预占会生成新凭证，旧凭证不能取消新预占；支付完成后取消或到期任务不会返还库存。当前仅支持单商品订单。

新建意向订单15分钟内可发起预占，预占本身再保留15分钟。超过预占截止时间后按关闭处理，不再恢复为可重新付款的意向单。过期任务每批最多处理100个 HELD 记录，单条失败记录日志、下一轮重试。多实例执行由数据库订单行锁和 HELD 条件迁移保证不会重复释放。

## 接口变化

- `POST /api/v1/peer-pay/pre-lock/{token}` 新增响应字段 `ownerToken`。它只在本次预占响应返回，不在公开详情或订单实体中暴露。
- `POST /api/v1/peer-pay/cancel-lock/{token}` 必须携带 `X-Reservation-Token: <ownerToken>`。持有分享链接本身不代表拥有取消其他付款人预占的权限。
- 前端真实付款仍未开放，因此本轮没有重新启用支付按钮或 Mock 流程。后续渠道收银接入时须保存本次预占凭证并用于显式取消，不应在任意页面卸载时无条件取消。
- 内部支付处理核对预占中的商品、SKU、商户、数量及有效期，核销后才交付；发卡异常时支付状态与预占核销一起回滚。

## 数据库与部署

新增表 `inventory_reservation`。新安装项目的 `db/schema.sql` 已包含表结构和到期查询索引。关闭自动 SQL 初始化的存量环境必须在启动新版本前执行：

```text
shop-b2b2c-backend/src/main/resources/db/migrations/002_inventory_reservation.sql
```

此文件是手动增量迁移，仓库尚未引入自动迁移框架；其中创建索引语句按一次性迁移使用，不要在已有相同索引时重复执行。表结构使用当前连接库，不创建数据库或切换数据库。部署前备份，执行后检查表和索引存在。

升级前旧版 Redis 订单锁不再用于新版本库存判断，原键自行 TTL 到期。旧版已 RESERVED_LOCK、但没有数据库预占记录的订单，在内部支付时保留 Sprint 1 的原子扣减路径，以免重复扣或凭空返还库存；旧锁没有独立取消凭证，等待其到期后由详情访问触发关闭；这些旧锁没有真实占用库存。迁移窗口仍应暂停旧版本写入，不能让新旧版本混跑：旧版支付会忽略数据库预占。
