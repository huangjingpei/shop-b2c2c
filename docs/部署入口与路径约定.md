# 部署入口与路径约定

本文作为当前工程部署路径的统一维护入口，说明三端产物、URL、网关及历史云脚本的关系。适用于人工审阅和隔离验证，不授权执行生产部署。当前状态：通用网关实现待人工验证；云脚本全链路及TLS尚未完成统一。

## 当前统一路径

采用商城根路径、管理端/console/的单机布局。后续部署适配以该布局为准，不按设备UA切换不同应用。

| 对象 | URL/base | 默认磁盘或服务位置 | 约定 |
| --- | --- | --- | --- |
| 商城 | `/`，VITE_APP_BASE=/ | `/opt/shop-b2b2c/www/storefront` | 商品、店铺、查单与代付均使用History路由 |
| 管理端 | `/console/`，VITE_APP_BASE=/console/ | `/opt/shop-b2b2c/www/admin` | `/console`跳转带斜杠路径；角色授权仍由后端负责 |
| 后端API | `/api/v1/...` | `127.0.0.1:8080` | Nginx保留完整URI及查询参数，不剥离/api前缀 |
| 应用存活 | `/healthz`代理`/api/v1/auth/health` | 上述同一个后端 | 后端不可达应失败，接口本身不验证DB/Redis |
| 依赖就绪 | `/readyz`代理`/api/v1/auth/ready` | 上述同一个后端 | DB连通及Redis持久化检查，失败503，不代表完整业务可用 |
| 公开附件 | `/uploads/` | `/opt/shop-b2b2c/uploads` | 仅放可公开附件，不将卡密/领取凭证放入静态目录 |
| 代付海报 | `/api/v1/peer-pay/poster/image/{sha256}.png`（后端只读接口） | `/opt/shop-b2b2c/uploads/order-posters` | 由`shop.poster.storage-dir`控制；文件名取分享凭证SHA-256，须纳入备份；多实例需共享目录 |

通用配置为deploy/nginx/nginx.prod.conf，作为http上下文中的include或站点文件使用，不能替代完整nginx.conf。使用前核对实际域名、根目录、端口、已有站点及权限；配置中的server_name _是待按环境核对的默认值。它提供HTTP路径基线，不包含证书和TLS上线配置，不应据文件名推定已具备完整生产条件。

Vite构建base与Vue Router的BASE_URL必须匹配；APP_FRONTEND_STOREFRONT_URL应为商城真实公开根地址，例如`https://shop.example.test`，不能误填管理端或旧/m路径。此示例域名不可直接用作真实环境。跨域来源使用APP_CORS_ALLOWED_ORIGINS设置真实来源值，保持与application.yml一致。

## 财务双人复核开关

后端通过 `shop.finance.dual-approval-required` / 环境变量 `FINANCE_DUAL_APPROVAL_REQUIRED` 控制调价、结算确认、充值确认与开店初始费率的复核强度。

- **生产必须为 `true`**，并至少配置两个具备财务权限的后台账号；同一账号操作与复核会被 403 拒绝。`prod` profile 启动时由 `FinanceApprovalConfigValidator` 校验，开关非 `true` 直接阻断启动并写明原因，不允许静默降级为单管理员。
- **开发/试点默认 `false`**，允许单管理员同人操作，但必须把 `approvalMode=SAME_OPERATOR` 落库；后端对每次真实资金操作写显式 WARN，管理端“财务复核与结算”“商户治理”页面展示“当前为单管理员模式”。该模式禁止用于生产。
- 管理端复核人入口（G31）：调价、开店初始费率在“商户管理”，结算批次与充值确认在“财务复核与结算”；候选人为除当前账号外的启用 SUPERADMIN。无第二账号时页面明确提示“需至少分配两个财务账号”。
- 严格模式未选复核人返回业务码 428（HTTP 428 Precondition Required），用于区分“缺复核人”和“同人 403”；宽松模式未传仍按操作人处理并落 `SAME_OPERATOR`。
- 两云 `server/04-deploy.sh` 已把 `FINANCE_DUAL_APPROVAL_REQUIRED` 列入 `REQUIRED_ENV_KEYS`：手工 `.env` 缺失即中止部署，取值只接受 `true|false`，其它拼写直接报错。`02-init-infra.sh` 生成的 `.env` 固定写入 `true`。
- 开关只影响复核强度，不改变金额计算、幂等键或账本语义。

## 历史入口关系

- 腾讯云模板的根商城/console布局已与当前约定一致，并补齐`/healthz`、`/readyz`与旧`/admin`、`/invite`、`/actuator`的404；部署脚本的可选前端跳过、数据库同步忽略错误、回滚及运行探针仍需逐项审阅，不能因路径接近而认定一键部署已验收。
- 阿里云自D35（Sprint 43）起也改为根商城：构建产出`www-storefront`与base`/`，部署目录`www/storefront`，`APP_FRONTEND_STOREFRONT_URL`派生为域名根地址，原`www-mobile/m`与`/m/`不再生成。真实构建、Nginx校验、历史站点切换与回滚仍待人工验证。
- `/m`、`/admin`、`/invite`和`/actuator/health`不是本通用网关支持的入口，明确返回404，不跳到不存在的注册页，不用SPA响应伪装健康成功。当前商城没有可复用的买家注册页。
- D37在Sprint 20新增有界就绪检查及腾讯云发布探针适配，待人工验证；存活接口仍不代表交易就绪，检查规则与运维前提见对应交付文档。

## 验证和后续工作

网关隔离验证、构建与部署适配边界见[Sprint 19交付](SPRINT_19_通用网关路径与存活入口.md)。先运行隔离用例，随后在开发环境用真实三端产物核对页面刷新、静态资源、API及公开分享链接。生产证书、已有站点兼容、systemd环境注入、数据库/Redis及回滚仍需单独验证；本轮没有修改系统服务或连接服务器。

部署后可执行只读烟测（D39）：

```bash
SMOKE_BASE_URL=https://实际域名 python3 -m unittest discover -s deploy/tests -p 'test_deployed_smoke.py' -v
```

未设置 `SMOKE_BASE_URL` 时该用例显式 skipped，跳过不是通过；烟测只发 GET，校验根商城、`/console/`、`/healthz`、`/readyz` 与旧入口 404，不覆盖支付渠道、数据库写入或证书链人工检查。
