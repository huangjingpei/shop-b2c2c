# Sprint 22：订单列表海报减载与按需读取

本文记录主台账D38中订单列表携带Base64海报的修复、接口兼容边界与手动验证命令。状态：**实现和测试用例已编写，待人工验证**。海报生成事务、Base64持久化及公开重新生成入口仍待处理，D38保持进行中。

关联D13局部Bug：新增数字路径参数的边界审阅发现，非法文本/Long越界绑定会落入通用500处理。本轮补共享类型绑定异常处理，返回HTTP/业务400且不回显输入；这是参数拒绝语义修复，不代表D13全部校验工作完成。

## 根因与实现范围

商家/平台订单列表直接读取完整TradeOrder，包含poster_url海报正文，商家页面也直接从列表打开图片。列表和统计读取会搬运无关大字段，随订单数量增长放大数据库、内存和响应负载。

本轮TradeOrderMapper的两类列表查询在SQL投影中排除poster_url，既有统计复用轻量结果。列表JSON结构保持原样，order.posterUrl变为null/空值；不是先SELECT全文再在Controller删除，也不会清空数据库海报。其他字段、服务凭证展示与D25统计口径保持原样；这不是完整白名单/分页改造，D30逐条查明细和全量列表仍保留。

新增GET `/api/v1/merchant/orders/{id}/poster`只读取已存poster_url，SQL同时限定订单ID和服务端当前商户，禁止缓存。空、缺失、他店统一404业务码，未绑定店铺拒绝；前端商户参数不能改变租户。该接口沿用现有R及BusinessException约定，404业务码不保证HTTP状态同步，客户端必须检查code。

该读取不生成海报、不锁订单、不更新状态/库存，不复用有行锁和回写行为的公开regeneratePoster。按需读取避免为查看列表附带CPU渲染或整单读取。新接口本身仍会返回单张完整Base64，尚未改为对象存储或流式图片。

## 商家页面兼容与边界

代付/推单入口通过peerPayType和非空peerPayToken等小字段判断，不再依赖列表posterUrl。点击后调用本店已存海报接口，显示加载/失败状态，成功后支持预览和下载；未保存的旧单允许显示入口但会明确提示未找到，不能据按钮推断图片已存在。

前端只接受现有生成器使用的PNG Base64 Data URL，拒绝外链、SVG、其他协议和无效格式；格式校验不证明图片内容可解码，图片错误事件会清空下载地址并提示失败。订单编号保留Long字符串精度，拒绝不安全数字、非法及越界编号。

关闭/卸载/切换订单使旧请求失效，打开新图片先清空上一次内容；不写localStorage，不记录异常原文。使用现有请求封装保留登录失效处理，错误在弹窗展示，避免重复全局提示。

本轮新增“已存海报”读取入口及列表空poster语义是代理对D38的技术细化，需前后端同时更新。仍依赖旧列表海报正文的外部客户端须改为按需读取，不宣称无行为差异的完全兼容。

## 测试用例与未验证项

MerchantOrderPosterTest使用Mock会话和Mapper验证合法读取、租户取值、无缓存、非法ID、缺失/空正文及未绑定店铺不读数据。Sprint1SecurityIntegrationTest追加H2大字段投影与内容保留、列表响应减载/统计不变、匿名拒绝、本店读取/他店与不存在拒绝、客户端租户参数无效和未绑定超管拒绝；未连接业务数据库。

同一单测追加独立MVC，验证非数字及Long越界路径由共享异常处理返回400、不回显原值、不触及Mapper。业务404仍沿用原HTTP约定，未批量改动所有业务异常状态。

storedPoster.test.mjs注入请求/渲染函数，覆盖入口、合法读取、非法ID/Long精度、外链/协议/Base64拒绝、业务/HTTP失败、异步切换、关闭失效及解码失败清理。占位数据只测试格式与状态，不证明真实PNG解码或浏览器下载通过。

未执行测试、构建、真实MySQL或浏览器联调。没有Schema/索引/数据迁移，无需重建数据库；海报创建仍在原事务中，公开重新生成仍存在CPU及锁负载，后续必须独立修复，不能因列表减载宣称D38全部完成。
